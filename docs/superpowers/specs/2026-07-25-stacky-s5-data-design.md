# S5 — Data slice design (TanStack Query, Svelte↔React parity)

**Goal:** Add a removable `tanstack-query` brick in a new single-occupancy `data` slot that gives a SvelteKit stack and a TanStack-Start stack an equivalent, idiomatic TanStack Query setup — a `QueryClient` provided to the app so components can run queries — with no wrong-framework dependency leaking. Continues the S1–S4 parity thesis. Approach **A** (router-level React integration, chosen by the user): SSR-integrated, not an explicit-client shim.

Everything below is validated empirically (two spikes): the end integration renders in a real browser on both frameworks, and the exact seam structure builds + type-checks + **lints** clean in both the no-query and with-query states.

## Two-part shape (why T1 restructures the tanstack brick)

TanStack Query provides its client differently per framework, and only one side fits stacky's additive inject-at-marker model without touching the framework brick:

- **Svelte is purely additive.** `@tanstack/svelte-query` exports `setQueryClientContext(client)` — an imperative Svelte-context setter that runs during component init. It drops straight into the **existing** `app-head` `<script>` seam of `+layout.svelte`. No `sveltekit`-brick change.
- **React needs the framework brick to grow seams.** The clean integration is `routerWithQueryClient(router, queryClient)` in `router.tsx`, which requires `createRouter({ context: { queryClient } })` **and** `__root.tsx` using `createRootRouteWithContext<{ queryClient: QueryClient }>()` (proven: without the `__root` change `tsc` fails — `routerWithQueryClient`'s `ValidateRouter` resolves to `never`). Because stacky injects at markers and cannot edit a token mid-expression, the `tanstack-start` brick must be restructured to carry the seams the query brick injects into. That restructure is **T1**; the query brick is **T2**.

## T1 — make `tanstack-start` query-ready (+ fix a React hydration bug)

### Restructured `router.tsx` (owned; content changes, still no golden)

```tsx
// routeTree.gen.ts is generated by the tanstackStart() vite plugin on `dev`/`build`
// (there is no standalone generator command); run a build/dev before `pnpm typecheck`.
import { createRouter } from '@tanstack/react-router'
import { routeTree } from './routeTree.gen'
// >>> stacky:router-imports
// <<< stacky:router-imports

export function getRouter() {
  // >>> stacky:router-setup
  // <<< stacky:router-setup
  const router = createRouter({
    routeTree,
    scrollRestoration: true,
    context: {
      // >>> stacky:router-context
      // <<< stacky:router-context
    },
  })
  // >>> stacky:router-wrap
  // <<< stacky:router-wrap
  return router
}
```

- `const router` + a **bare statement** in `router-wrap` (the query brick injects `routerWithQueryClient(router, queryClient)`, which mutates `router.options` in place and returns the same ref — verified from source). `let router` + reassign would trip `prefer-const` in the no-query default; `const` + statement is lint-clean.
- Empty `context: {}` in the no-query default is a plain object literal — no lint rule touches it.

### Restructured `__root.tsx` (composed; goldens regenerate)

Change `createRootRoute({...})` → `createRootRouteWithContext<RouterContext>()({...})`, add a `root-imports` seam and a `RouterContext` type with a `root-context` member seam. **Keep** the `app-head` / `app-shell` seams, the document shell (`<html>/<head>/<body>`, `HeadContent`, `Scripts`), `head:` meta, and `Outlet` inside `RootDocument`:

```tsx
// >>> stacky:app-head
// <<< stacky:app-head
import {
  Outlet,
  createRootRouteWithContext,
  HeadContent,
  Scripts,
} from '@tanstack/react-router'
import type { ReactNode } from 'react'
// >>> stacky:root-imports
// <<< stacky:root-imports

type RouterContext = object & {
  // >>> stacky:root-context
  // <<< stacky:root-context
}

export const Route = createRootRouteWithContext<RouterContext>()({
  head: () => ({
    meta: [
      { charSet: 'utf-8' },
      { name: 'viewport', content: 'width=device-width, initial-scale=1' },
      { title: 'stacky' },
    ],
  }),
  component: RootComponent,
})

// … RootComponent / RootDocument unchanged …
```

- **`type RouterContext = object & { … }` is the empty-safe idiom.** The `@typescript-eslint/no-empty-object-type` rule explicitly exempts `{}` when it is an operand of an `&` intersection (confirmed from the rule's source), so the empty (no-query) default lints clean with **no eslint config change**. `interface X {}` and `type X = {}` both fail that rule; the intersection form does not.

### Fix the React hydration bug (found by the S5 spike)

The tanstack brick's `fragments/plugin.ts` only pushes `tanstackStart()`. Without `@vitejs/plugin-react`, the generated React app throws `ReferenceError: React is not defined` on hydration — **even in a production build** (reproduced on a vanilla, zero-query scaffold; the T-completeness `vite preview` check saw the 200 SSR but never checked the browser console). Fix, in the same brick T1 touches:

- `fragments/plugin.ts`: add `import react from '@vitejs/plugin-react'` and `stackyPlugins.push(react())` alongside `tanstackStart()`.
- `fragments/package.json`: add `@vitejs/plugin-react ^4.0.0` (devDependency). **`^4`, not `^6`** — v6 requires Vite 7's `vite/internal` export that the `vite` brick's pinned `^6.0.0` lacks. (The `vite@6` vs `@tanstack/react-start` `>=7` peer mismatch remains an F1 item.)

## T2 — the `tanstack-query` brick

### Slot and brick

- New slot `data`, `single = true`, at the END of the chain (after `auth`). Slot order: `… orm → auth → data`.
- Brick `tanstack-query` in slot `data`.
- `[requires] http-origin = "*"` — query needs a web framework's layout/router to inject into. The removable-census loop always includes a web brick (`base = { vite, [fw] }`), so this is satisfied there with no special handling (unlike the `sql-db` bricks).

### Contributions (framework-gated via `when`)

| Contribution | `when="svelte"` | `when="react"` |
|---|---|---|
| Provider wiring | inject into `app-head` (`+layout.svelte`): `import { QueryClient, setQueryClientContext } from '@tanstack/svelte-query'` + `setQueryClientContext(new QueryClient())` | inject into `router-imports` (`import { QueryClient } from '@tanstack/react-query'` + `import { routerWithQueryClient } from '@tanstack/react-router-with-query'`), `router-setup` (`const queryClient = new QueryClient()`), `router-context` (`queryClient,`), `router-wrap` (`routerWithQueryClient(router, queryClient)`), `root-imports` (`import type { QueryClient } from '@tanstack/react-query'`), `root-context` (`queryClient: QueryClient`) |
| Owned demo (unrouted) | `src/lib/QueryDemo.svelte` — `createQuery(() => ({ queryKey, queryFn }))` | `src/lib/QueryDemo.tsx` — `useQuery({ queryKey, queryFn })` |
| package.json deps | `@tanstack/svelte-query ^6.0.0` | `@tanstack/react-query ^5.0.0`, `@tanstack/react-router-with-query ^1.0.0` |

- **Demo components are owned and unrouted** (like the vitest brick's `Counter`), so they type-check and demonstrate the API without becoming a second publisher of the `app-shell` seam (iconify already publishes there; a second publisher would hit the tracked injection-point-uniqueness gap). They exercise the deps' types; the provider's runtime behavior was proven by the spike (both frameworks rendered a live query).
- **Svelte v6 API:** `createQuery(() => ({ … }))` (thunk form; v6 dropped stores/`$`-prefix).

### Direct-dep discipline

Every imported package is a direct dependency of the matching gated `package.json`: svelte-query (svelte side, imported by the `app-head` inject + demo); react-query + react-router-with-query (react side, imported by the router/root injects + demo). No wrong-framework query package leaks.

### Testing / verification

- **Removable census** (`round-trip.test.ts:37`) `+= tanstack-query` (sorts between `tailwind` and `typecheck`); **full brick enumeration** (`bricks.test.ts:13`) `+= tanstack-query` (between `tailwind` and `tanstack-start`). Both strict `toEqual`. Round-trip byte-identity holds — the brick's seam injects (react) and the svelte app-head inject revert cleanly on removal (additive-seam removal, like iconify/better-auth); T1's empty seams are the revert target on the react side.
- **Parity capstone** (both stacks, one `it`): svelte stack → `+layout.svelte` has `setQueryClientContext` + `@tanstack/svelte-query` dep, no react-query; react stack → `router.tsx` has `routerWithQueryClient` + `queryClient` in `createRouter` context, `__root.tsx` has `createRootRouteWithContext` + `queryClient: QueryClient`, deps `@tanstack/react-query` + `@tanstack/react-router-with-query`, no svelte-query. Cross-framework isolation asserted both directions.
- **Goldens:** composed `sveltekit.query.layout.svelte`, `tanstack.query.router.tsx`, `tanstack.query.root.tsx` (the seam-injected versions). Owned demo components are byte-identical to source → no golden. package.json deps asserted inline in the capstone.
- **Runtime smoke (best-effort):** scaffold `{ vite, sveltekit, tanstack-query }` and `{ vite, tanstack-start, tanstack-query }`; `pnpm install`, `pnpm build`, `pnpm typecheck` clean on both. (The live query render was already proven by the spike; not re-run as a gate.)
