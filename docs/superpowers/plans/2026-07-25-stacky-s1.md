# S1 — Styling Slice (Tailwind + Iconify) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a framework-agnostic `tailwind` brick and a framework-specific `iconify` brick, growing a minimal app shell in each framework, and prove the Svelte↔React parity split byte-for-byte.

**Architecture:** Reuse S-DB's `when` gate against a new axis (framework *family* capability `svelte`/`react`) and phase-2a's injection-point mechanism. Each framework grows a root layout that publishes two injection points (`app-head`, `app-shell`); Tailwind rides existing seams ungated; Iconify ships `when`-gated Svelte/React variants. A prerequisite refactor upgrades the `vite-plugins` seam from single- to multi-contributor.

**Tech Stack:** TypeScript (ESM, strict), pnpm workspace, vitest; Tailwind CSS v4 (`@tailwindcss/vite`), Iconify (`@iconify/svelte`, `@iconify/react`).

**Design spec:** `docs/superpowers/specs/2026-07-25-stacky-s1-styling-design.md`

## Global Constraints

- **ESM only, Node ≥22, TypeScript strict, no `any` in `packages/core`.** No core engine changes are required by this plan — `when` (gate.ts) and the injection-point mechanism already exist; reuse them unchanged.
- **Column-0 markers.** Every injection marker (`// >>> stacky:app-head`, `<!-- >>> stacky:app-shell -->`, etc.) must sit at column 0 in its host file, even inside `<script>` or JSX, because the inject engine writes fragment bodies flush-left. Indented markers produce indentation-mismatched output.
- **Byte-stability.** Composed `package.json` is recursively key-sorted (order-independent); `compose.yml` uses `sortMapEntries`. Fragments are joined with a single `\n` in graph order (slot declaration order, then brick name). Slot order in `bricks/slots.toml` is `container → build → web → css → icons → edge → db-engine → orm`.
- **Family capabilities are additive.** `sveltekit` provides `["http-origin", "svelte"]`; `tanstack-start` provides `["http-origin", "react"]`. Do not remove `http-origin`.
- **Registry censuses are strict.** Several tests assert the exact set of bricks/removables (`round-trip.test.ts`, possibly `bricks.test.ts`, `resolve.test.ts`). When a census fails because a new brick/capability legitimately exists, update the expected value to the new reality — keep it a strict `toEqual`/`toMatchObject`, never loosen the matcher.
- **Git:** one short conventional-commit subject line per commit (e.g. `feat(vite): make vite-plugins seam multi-contributor`). No `Co-Authored-By` trailer. Run hooks normally.
- **Dependency version ranges** use caret-major style matching sibling fragments (e.g. `^4.0.0`). Confirm each added package's current major resolves on npm; if a major differs from the value below, use the real current major and note it.
- **`.svelte` files** must be validated via the Svelte MCP (`mcp__plugin_svelte_svelte`) / svelte-file-editor agent. The **TanStack Start** root/route files must be checked against current `@tanstack/react-router` + `@tanstack/react-start` conventions (context7) — they are the only framework-convention-sensitive files in this plan. Both are **minimal injection hosts**, not production-complete framework entries; full framework-completeness (e.g. `app.html`, `router.tsx`, SSR document shell) is out of scope for S1 (runtime-render validation is deferred).

```ts
it('tailwind wires the vite plugin, css import, and app.css (both stacks, byte-identical css)', async () => {
  async function bits(fw: 'sveltekit' | 'tanstack-start') {
    const dir = await mkdtemp(join(tmpdir(), `stacky-tw-${fw}-`))
    await converge(dir, { bricks: { vite: {}, [fw]: {}, tailwind: {} }, overrides: {} })
    const css = await readFile(join(dir, 'app/src/app.css'), 'utf8')
    const viteCfg = await readFile(join(dir, 'app/vite.config.ts'), 'utf8')
    const layoutPath = fw === 'sveltekit' ? 'app/src/routes/+layout.svelte' : 'app/src/routes/__root.tsx'
    const layout = await readFile(join(dir, layoutPath), 'utf8')
    return { css, viteCfg, importsCss: layout.includes("import '../app.css'") }
  }
  const sv = await bits('sveltekit')
  const rx = await bits('tanstack-start')
  expect(sv.css).toContain('@import "tailwindcss"')
  expect(sv.viteCfg).toContain('stackyPlugins.push(tailwindcss())')
  expect(rx.viteCfg).toContain('stackyPlugins.push(tailwindcss())')
  expect(sv.importsCss && rx.importsCss).toBe(true)
  expect(sv.css).toEqual(rx.css) // Tailwind contributes byte-identical css on both stacks
})
```

```ts
it('iconify emits framework-native bytes on each stack (parity capstone)', async () => {
  async function styled(fw: 'sveltekit' | 'tanstack-start') {
    const dir = await mkdtemp(join(tmpdir(), `stacky-parity-${fw}-`))
    await converge(dir, { bricks: { vite: {}, [fw]: {}, tailwind: {}, iconify: {} }, overrides: {} })
    return dir
  }
  const svDir = await styled('sveltekit')
  const rxDir = await styled('tanstack-start')
  const svLayout = await readFile(join(svDir, 'app/src/routes/+layout.svelte'), 'utf8')
  const rxRoot = await readFile(join(rxDir, 'app/src/routes/__root.tsx'), 'utf8')
  const svPkg = await readFile(join(svDir, 'app/package.json'), 'utf8')
  const rxPkg = await readFile(join(rxDir, 'app/package.json'), 'utf8')

  expect(svLayout).toContain("import Icon from '@iconify/svelte'")
  expect(rxRoot).toContain("import { Icon } from '@iconify/react'")
  expect(svPkg).toContain('@iconify/svelte')
  expect(rxPkg).toContain('@iconify/react')
  expect(svPkg).not.toContain('@iconify/react')   // wrong-framework dep never leaks
  expect(rxPkg).not.toContain('@iconify/svelte')

  const render = '<Icon icon="ph:heart" />'       // render markup is byte-identical
  expect(svLayout).toContain(render)
  expect(rxRoot).toContain(render)
```
