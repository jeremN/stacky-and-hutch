# S2 — Quality Slice (lint · format · typecheck) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add ESLint (flat config), Prettier, and type-checking to the generated app, each first-class on both framework families, reusing S1's `when`-gated variant + additive `.push()` config-seam patterns.

**Architecture:** New `quality/` concern with three single-occupancy slots (`lint`, `format`, `typecheck`). `eslint` owns a flat-config file publishing an `eslint-config` seam and self-injects `when`-gated Svelte/React blocks; `prettier` is framework-agnostic with a gated Svelte plugin; `typecheck` is fully gated (svelte-check vs tsc). Frameworks grow an owned `tsconfig.json`; the SvelteKit `check` script is removed (moves to the quality slice).

**Tech Stack:** TypeScript/pnpm/vitest; ESLint 9 flat config, typescript-eslint, eslint-plugin-svelte, eslint-plugin-react, eslint-config-prettier; Prettier 3 (+ prettier-plugin-svelte); svelte-check.

**Design spec:** `docs/superpowers/specs/2026-07-25-stacky-s2-quality-design.md`

## Global Constraints

- **No core engine changes.** `when` (gate.ts) and injection points already exist; reuse them.
- **Column-0 markers** in every owned config file (`// >>> stacky:eslint-config`, `// >>> stacky:prettier-plugins`), so injected `.push()` bodies land flush-left — matching the `vite-plugins` seam.
- **Additive `.push()` seam convention** (established by `vite-plugins`): the owned config file pre-declares a mutable array/object; contributors push into it inside the marker region. Never redeclare.
- **Direct-dep discipline (the S1 `@tanstack/react-router` lesson):** every package a generated config imports or a script invokes must be a direct dependency in the matching `package.json` fragment. Gated deps go in gated fragments.
- **Flat-config API is version-sensitive — VERIFY.** Before finalizing any `eslint.config.js` block or Prettier config, verify current major versions (`npm view <pkg> version`) AND the exact flat-config export shape via context7 (`resolve-library-id` then `query-docs`) for: `typescript-eslint` (`tseslint.configs.recommended`), `eslint-plugin-svelte` (`configs['flat/recommended']` vs `configs.recommended`), `eslint-plugin-react` (`configs.flat.recommended`), `eslint-plugin-react-hooks` (flat support), `eslint-config-prettier` (flat-config object; v9+). Use the CURRENT correct API/majors; the baselines below are a starting point, not gospel.
- **Registry censuses are strict.** Update `round-trip.test.ts` removable census and any `bricks.test.ts` enumeration to the new reality with strict `toEqual`; never loosen.
- **Run vitest from repo root** (`pnpm exec vitest run …`, `-u` to regenerate goldens); there is no `vitest` script in `@stacky/core`.
- **Full gate before each task is done:** `pnpm vitest run && pnpm tsc -b` green; `git diff --check` clean. Confirm only intended goldens moved.
- **Git:** one short conventional-commit subject per commit; NEVER a `Co-Authored-By` trailer; run hooks normally.
- **Slot order** in `bricks/slots.toml`: `container → build → web → css → icons → lint → format → typecheck → edge → db-engine → orm`.
