# S3 Testing Slice Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a removable `vitest` brick (new single-occupancy `test` slot after `typecheck`) that gives a SvelteKit stack and a TanStack-Start stack an equivalent Vitest + jsdom test surface with framework-correct component testing and no wrong-framework dependency leaking.

**Architecture:** The brick owns `app/vitest.config.ts`, which `mergeConfig`s the app's `vite.config.ts` (inheriting the framework's compile plugin) and carries a `testPlugins` `.push()` seam. The Svelte variant gate-injects `svelteTesting()` from `@testing-library/svelte/vite`; React needs no plugin. Component tests, testing-library deps, and the plugin inject are all `when`-gated; the config/setup/scripts and a tiny unit test are framework-agnostic.

**Tech Stack:** Vitest 4, jsdom, `@testing-library/{jest-dom,svelte,react,dom}`, Svelte 5 runes, React 19.

## Global Constraints

- **Git:** one short conventional-commit subject line per commit (e.g. `feat(test): add vitest brick agnostic core`); NEVER a `Co-Authored-By` trailer; run hooks normally (no `--no-verify`).
- **Direct-dep discipline:** every package a composed/owned file imports must be a direct dependency in the matching (gated) `package.json` fragment for that stack; no wrong-framework package may leak into the other stack.
- **Byte-stability/determinism:** composed `package.json` is recursive-key-sorted; markers sit at column 0; the engine writes fragment/inject bodies flush-left.
- **Slot order is merge order.** The `test` slot goes after `typecheck`, before `edge`.
- **`.push()`-into-pre-declared-array seam convention:** the owned file pre-declares a mutable typed array; contributors push inside the column-0 marker region; ES imports in the region hoist (legal, established).
- **Test command form (this repo):** run from the repo ROOT: `pnpm exec vitest run round-trip -u` to (re)generate goldens, then `pnpm vitest run` for the full suite, then `pnpm tsc -b`. Do NOT use `pnpm --filter @stacky/core vitest run`.
- **Concern folder:** the brick lives at `bricks/quality/vitest/` (testing is a quality concern, alongside `eslint`/`prettier`/`typecheck`).
- **Runtime note:** the stacky suite composes files and checks bytes/goldens/census; it does NOT execute Vitest inside generated apps. Component-test *runtime* correctness is verified best-effort by the implementer (see Task 3 optional smoke), not by the automated gate.

```ts
it('[tanstack-start] vitest gates react component testing; no svelte plugin leaks', async () => {
  const dir = await mkdtemp(join(tmpdir(), 'stacky-vitest-rx-'))

it('vitest gives both stacks a test surface with framework-correct component testing (parity)', async () => {
  async function bits(fw: 'sveltekit' | 'tanstack-start') {
    const dir = await mkdtemp(join(tmpdir(), `stacky-vitest-parity-${fw}-`))
    await converge(dir, { bricks: { vite: {}, [fw]: {}, vitest: {} }, overrides: {} })
    const cfg = await readFile(join(dir, 'app/vitest.config.ts'), 'utf8')
    const pkg = JSON.parse(await readFile(join(dir, 'app/package.json'), 'utf8')) as {
      scripts: Record<string, string>
      devDependencies: Record<string, string>
    }
    return { cfg, pkg }
  }
  const sv = await bits('sveltekit')
  const rx = await bits('tanstack-start')
  // both stacks run tests the same way
  expect(sv.pkg.scripts.test).toBe('vitest run')
  expect(rx.pkg.scripts.test).toBe('vitest run')
  // right testing library present, wrong absent — in package.json
  expect(sv.pkg.devDependencies).toHaveProperty('@testing-library/svelte')
  expect(sv.pkg.devDependencies).not.toHaveProperty('@testing-library/react')
  expect(rx.pkg.devDependencies).toHaveProperty('@testing-library/react')
  expect(rx.pkg.devDependencies).not.toHaveProperty('@testing-library/svelte')
  // the svelteTesting plugin is gated to svelte only — in the config text
  expect(sv.cfg).toContain('svelteTesting()')
  expect(rx.cfg).not.toContain('svelteTesting')
})
```
