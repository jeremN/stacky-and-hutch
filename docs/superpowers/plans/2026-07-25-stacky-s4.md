# S4 Auth Slice Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a removable `better-auth` brick (new single-occupancy `auth` slot after `orm`) giving a SvelteKit stack and a TanStack-Start stack an equivalent email/password auth surface — engine-gated server instance (built-in adapter), framework-gated client + catch-all route — with no wrong-framework dependency leaking.

**Architecture:** The brick owns `app/src/lib/auth.ts` (engine-gated Postgres `Pool` / SQLite `Database`, `emailAndPassword` enabled, a `stacky:auth-plugins` `.push()` seam). SvelteKit and TanStack each get a gated `auth-client.ts` and a catch-all API route calling the framework-agnostic `auth.handler(request)`. React injects `tanstackStartCookies()` into the seam. better-auth manages its own tables via `@better-auth/cli migrate` — no drizzle coupling.

**Tech Stack:** better-auth 1.6, `@better-auth/cli`, `pg`/`better-sqlite3` (from the engine bricks), SvelteKit, TanStack Start.

## Global Constraints

- **Git:** one short conventional-commit subject line per commit; NEVER a `Co-Authored-By` trailer; run hooks normally.
- **Direct-dep discipline:** every package a composed/owned file imports is a direct dependency in `app/package.json`. `better-auth` is added by this brick; `pg`/`better-sqlite3` come from the engine bricks (auth requires an engine) — do NOT re-declare them.
- **Byte-stability/determinism:** composed `package.json` recursive-sorted; markers at column 0; `const plugins: BetterAuthPlugin[] = []` is typed (avoids the `TS7034` empty-array trap, same lesson as the vite plugin seam).
- **Slot order is merge order.** The `auth` slot goes after `orm` (end of chain).
- **Engine gating** uses the `pg-driver` / `sqlite-driver` capabilities (provided by the postgres/sqlite bricks) — the same gating the drizzle brick uses. **Framework gating** uses `svelte` / `react`.
- **Test command form (repo root):** `pnpm exec vitest run round-trip -u` to regenerate goldens, then `pnpm vitest run`, then `pnpm tsc -b`, then `git diff --check`. Do NOT use `pnpm --filter @stacky/core vitest run`.
- **Concern folder:** the brick lives at `bricks/auth/better-auth/` (new `auth` concern folder).
- **Runtime note:** the stacky gate checks generated bytes/goldens/census; it does not run the generated app. Full sign-in requires a live DB + `better-auth migrate` — best-effort only.

it('better-auth gives both stacks auth with framework-correct client + route (parity)', async () => {
  async function bits(fw: 'sveltekit' | 'tanstack-start') {
    const dir = await mkdtemp(join(tmpdir(), `stacky-auth-parity-${fw}-`))
    await converge(dir, { bricks: { vite: {}, [fw]: {}, postgres: {}, 'better-auth': {} }, overrides: {} })
    const client = await readFile(join(dir, 'app/src/lib/auth-client.ts'), 'utf8')
    const src = await readFile(join(dir, 'app/src/lib/auth.ts'), 'utf8')
    const pkg = JSON.parse(await readFile(join(dir, 'app/package.json'), 'utf8')) as {
      dependencies: Record<string, string>
    }
    return { client, src, pkg, dir }
  }
  const sv = await bits('sveltekit')
  const rx = await bits('tanstack-start')
  // both get better-auth
  expect(sv.pkg.dependencies).toHaveProperty('better-auth')
  expect(rx.pkg.dependencies).toHaveProperty('better-auth')

  expect(sv.client).not.toContain('better-auth/react')
  expect(rx.client).toContain('better-auth/react')
  expect(rx.client).not.toContain('better-auth/svelte')
  // the tanstack cookie plugin is gated to react only
  expect(sv.src).not.toContain('tanstackStartCookies')
  expect(rx.src).toContain('tanstackStartCookies()')
  // committed goldens for the composed auth.ts (seam empty on svelte, cookie push on react)
  await expect(sv.src).toMatchFileSnapshot('./golden/sveltekit.auth.ts')
  await expect(rx.src).toMatchFileSnapshot('./golden/tanstack.auth.ts')
